## 执行

在项目目录运行，输出目录必须使用新名称：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.run_scb_pilot --out runs/scb-real-new
```

也可以先采集、核对截图，再开始模型：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.run_scb_pilot --out runs/scb-real-new --capture-only
.\.venv\Scripts\python.exe -X utf8 -m scripts.run_scb_pilot --out runs/scb-real-new --resume
.\.venv\Scripts\python.exe -X utf8 -m scripts.score_scb_pilot --run runs/scb-real-new
```

`--resume`继续使用同一批冻结证据，已经成功保存的模型输出不会重新调用。若模型、提示词或提取配置有变化，应使用新的对比试验目录，避免将两个版本混成同一次试验。失败记录保留；不因为重试成功自动消除历史异常。

查看`benchmark.html`获取测评摘要，`review.html`逐项查看模型输出与异常，`evidence/index.html`查看官网证据。测评参考只用于评分，不发送给模型，不代表用户已审批。

同一表包含Personal、Priority Banking、Priority Private三档，能够检查Personal排序值与全客群最高值是否分别处理。同时官网正文与关联PDF存在起始日期差异，适合验证跨来源冲突的复核流程。

由于完整证据为一个报价区域加两页PDF，本试点单独使用3张图、32K上下文和18,000字上限。不会修改原`project.local.json`。这些是输入容量配置，准确率、内存和耗时必须记录；不能将配置检查通过当成GPU加速已经启用。

已扩展`doctor`：有已加载模型时会报告是否实际使用GPU；没有加载模型时明确说明无法确认。

## GPU检查记录

此次执行时，本机Ollama返回`size_vram=0`，日志显示`offloaded 0/33 layers to GPU`，模型实际在CPU运行。NVIDIA驱动读取为566.07，Ollama安装目录仅发现`mlx_cuda_v13` GPU库目录。

这提示需要检查安装完整性及驱动/运行库兼容性。NVIDIA官方列出的CUDA 13.x驱动最低分支为580；该事实不能单独证明这是唯一原因。当前没有修改显卡驱动、安装目录或重启用户服务。

来源：[NVIDIA CUDA兼容性](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html)、[Ollama故障排查](https://docs.ollama.com/troubleshooting)。

## 输出格式的兼容性检查

本机Ollama服务版本为0.18.2。官方项目记录了Qwen3.5在`think=false`时忽略结构化输出约束的问题，并在后续代码中修复。该记录是排查线索，不能仅凭相似症状认定为本次失败的唯一原因。

可以先用很小的本地请求对比普通输出与带格式约束的输出，避免每次都重跑整批网页和图片：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.probe_local_model --out runs/model-probe-new
```

该检查不提取利率，不表示模型准确率通过；原始响应会保存到独立目录。正式提取也已增加原始响应留存，格式无效或响应为空时保持失败状态。

来源：[官方问题记录](https://github.com/ollama/ollama/issues/14645)、[后续修复](https://github.com/ollama/ollama/pull/15901)。
