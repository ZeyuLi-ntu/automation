# 下一步：从软件测试进入真实银行试点

## 阶段目标

生成一份可逐项追溯的SGD促销调研表和彩虹表，并测出漏项、错误字段、人工修改量和耗时。已有测试证明规则与导出程序能够工作；当前尚未证明本地模型能准确提取真实银行页面。

## 顺序和交付物

| 顺序 | 工作 | 交付物 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 安装Ollama及Qwen3.5 4B，运行文字与截图各一次实际推理 | 模型版本、原始响应、耗时、显存/内存观察记录 | 两路确实调用本地模型；视觉能识别利率表；输出完整JSON |
| 2 | 选一家银行的一张真实利率表及所有关联条款 | 同一采集时间的网页文字、PNG/PDF、人工标准答案 | 每项金额、客群、渠道、期限、有效期均有证据；不能只记录利率数字 |
| 3 | 在同一冻结证据上运行两路提取并对照人工答案 | 逐字段对比、漏项表、共同错误表 | 每个已知报价要么正确找到，要么进入明确异常；不得默默消失 |
| 4 | 扩展RHB、SCB、UOB三家候选银行，核实产品身份与模板位置 | 已确认来源、产品目录、期限映射、模板映射 | 已知客群/档位/期限全部覆盖，新增产品有确定插入位置 |
| 5 | 用16号工作簿作为模板生成当前采集日的试点输出 | 新调研表、新彩虹表、本期逐项检查、证据索引 | Personal排序与全客群最高汇总分别正确；保留历史；所有异常已解释 |
| 6 | 再运行一期，验证跨期行为 | 第二期输出和变更清单 | 不重复插入产品；并列顺序稳定；人工修正延续；消失不误判为停供 |

三家银行是建议试点范围，具体产品与页面仍需核实。RHB用于检查Personal/Premier，SCB用于多客群档位，UOB用于期限变化和产品状态。可按网站可访问性调整顺序；先完成一家，再扩大。

## 人工标准答案至少包含

银行、稳定产品ID、币种、促销/挂牌、实际期限、客群、渠道、起存金额及边界、等值币种、新资金条件、利率单位和口径、有效期、产品状态、证据URL/页码/截图位置。

标准答案依据同一批当期证据核实。9号/16号文件用于排版和业务规则回归，已有爬虫文件用于寻找差异线索；它们都不能自动充当今天利率的正确答案。缺少当期网页存档时，不用今天网页回填9号或16号。

## 必须覆盖的案例

- 普通Personal低于Premier，但排序仍使用Personal。
- 同产品多个Personal金额/渠道档位，取有效Personal最高值并保留对应条件。
- 4M/8M/10M等非标准期限，映射只对已确认产品生效，并保留实际期限。
- 条件改变但利率未变；只变有效期；网页链接失效但官网仍有新入口。
- 两路利率一致但金额或客户资格不一致；两路都漏掉同一报价。
- 本期找不到、明确停供、已过期，三种状态分别处理。
- 视觉表格跨截图、PDF或条款在另一个页面；上下文或输出超限。

## 验收数字怎样记录

| 指标 | 计算方式 |
| --- | --- |
| 报价覆盖率 | 正确匹配的标准答案记录数 / 标准答案记录总数 |
| 字段准确率 | 利率、金额、客群、期限等分别统计正确数 / 应核对数 |
| 共同错误 | 两路同错或同漏的数量，单独列出，不能被“一致率”掩盖 |
| 人工处理量 | 需修改或补充的记录数，以及实际复核分钟数 |
| 运行耗时 | 采集、文字模型、视觉模型、人工、导出分别计时 |

第一轮以“人工复核后的输出无未解释错误、无未处理异常”为交付门槛，不把小样本100%当成未来准确率保证。先积累至少两期真实样本，再决定是否缩小人工复核范围。初期全部变化项和异常项仍须复核。
