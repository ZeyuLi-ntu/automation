# 剩余促销、挂牌与本地自动化实施规划

日期：2026-09-27。本文是后续执行方案，不表示未接入范围已经实现。本轮不改变现有工作簿或批准历史底稿。

## 目标与原则

采集、文字/视觉推理、规则检查、人工修正、Excel与调度全部在本机。银行网页需要联网；项目不使用云端模型。GPT用于一次性开发和必要维护，日常任务由固定程序执行。

开发按“来源页面/附件＋版式”组织：一个多币种页面只采集一次，保存原始证据，再按币种、产品、客群、期限和金额档拆分。来源总数、报价行数、表格区域数分别统计，不能把“有链接”当成“已覆盖”。

## 实际范围

现有底稿包含：SGD/USD/CNY促销、其他外币促销；SGD/USD/CNY/AUD/NZD/CAD/HKD/EUR/GBP挂牌；Premier Rates和最高报价汇总。彩虹表有SGD Promotional Rate、SGD Board Rate、USD Rate + Other Currency Rates三个现有页。

继续排除MariBank、Trust；其余已确认排除、只留明细、期限归组、排序、颜色、历史类型和人工修正规则不变。USD与CNY挂牌沿用历史列式，其他挂牌沿用原矩阵。新产品仍在同一银行区块内增加明细。具体规则以config/workbook-policy.json及已有测试为准。

## 分阶段实施

| 阶段 | 主要工作 | 可检查交付与通过条件 |
|---|---|---|
| 0. 固定范围与验收依据 | 建立银行×币种×促销/挂牌×产品/客群清单；登记来源、目标表页、行/矩阵位置、实际采集日期及排除项。整理人工核实的固定证据与预期结果。 | 现有模板的每个目标区域有“待接入/已核验/排除/缺失”等明确状态；测试依据不直接复制模型答案。 |
| 1. 共用能力与SGD收尾 | 所有来源从链接登记读取，替换分散固定网址；统一币种、利率类型、金额币种、产品身份和日期字段；人工界面去除SGD固定标签。单独处理Maybank连接和ICBC口径。 | 旧SGD用例通过；同银行同期限的不同币种、挂牌/促销及客群不会混合；手动修正不会串币种。未解决项目明确显示缺失/待核。 |
| 2. 挂牌试点 | 选2—3家结构简单、来源可访问的银行，跑通SGD/USD挂牌。开发网页表格、PDF表格共用采集/解析模块；确定性解析结果与独立视觉读取核对，保留现有本地文字路线。 | 人工确认样本的利率、币种、实际期限、客群和金额边界逐项完全匹配；无漏行/重复行；USD历史列与SGD矩阵均按原样式更新。 |
| 3. 批量扩展挂牌 | 复用已验收版式，扩展CNY及AUD/NZD/CAD/HKD/EUR/GBP；同源多币种表一次采集、分别写入。 | 各币种独立完整性检查；CNY/RMB按明确配置映射，CNH等口径差异不静默合并；未支持币种不标记已检查。 |
| 4. 扩展促销 | 先USD，再CNY，再其他外币；普通定存先接入，投资搭配、新资金、分层财富资格等复杂产品单独处理。 | 利率、资格、渠道、金额、有效期、附加资金等影响报价的条件有证据；名义/有效利率不混淆；促销不混挂牌，过期活动不作为有效报价。 |
| 5. 汇总与彩虹表 | 同步现有三页彩虹表与最高报价汇总；单独明确Premier Rates的来源、资格和所属比较区域。 | 同一币种/比较范围内正确选择排序值；并列顺序、颜色、实际期限备注、银行合并区、历史滚动与最新两列差额全部通过检查。 |
| 6. 完整本地运行 | 按银行/来源保存进度、错误分类、有限重试、缓存、恢复、日志和备份；本地Windows调度；依赖版本固定并迁至可配置独立目录。 | 关闭GPT聊天后可执行完整本地任务；成功批次不因其他银行失败重跑；失败区域不填未验证数字；日常报告能明确完整/部分完成。 |
| 7. 连续运行验收 | 使用历史固定证据回放、模拟连续多期变动，并检查真实周运行；演练新增产品、消失、改网址、条件变更、人工修正与恢复。 | 建议至少两期真实运行核对；历史无污染、无重复日期列、无跨期误用修正。全流程结果经人工检查后，再逐步减少重复检查。 |

阶段0—1是批量扩展的共同前提。阶段2—5按版式分小批交付，每批通常2—3家；同一页面覆盖多个币种可一起验收。Maybank网络故障单独跟踪，不阻止其他银行开发，但不得宣称该行已完成实时采集。

## 精度与发布边界

1. 来源完整性：核对预期银行/产品、表头、行数、币种数、翻页/折叠区及关联条款。官网明确无促销、访问失败、页面改版是不同状态，不能合并。
2. 数据准确性：独立比较文字和图像的报价、币种、期限、金额边界、客群、渠道及有效期；新条件需补充结构化字段和对照样本，不能仅比较利率数值。
3. 单位与语义：核对百分数、小数、年/月/天、名义/有效、金额币种和新资金等。异常阈值仅触发复核，不自动把异常数字改成“合理值”。
4. 插表与历史：从已保存的Excel重新读回，比较输入、主报价、汇总、排序、公式缓存和历史；不新增错误单元格、不损坏原格式或合并区、不在报价格显示涨跌箭头。
5. 人工依据：每种新格式首次接入逐项对照；新增、变化和异常必须复核。稳定后可对未变化项抽查并定期全量复核，但不自动降低用户已确认的检查要求。

对人工核实的固定验收样本，关键字段和覆盖行数要求100%匹配；这只是该样本的通过条件，不是对所有未来网页作100%准确承诺。另用未参与适配的页面/期次检验，避免只通过已知样本。单纯“LLM与VLM一致率”不能当成准确率。

发现分歧或证据不完整时，隔离对应报价/产品。其他银行继续采集；部分结果仅生成标明缺失的待复核副本，不跳过核心拦截。正式历史底稿只由用户明确确认。

## 如何减少GPT对话用量

| 工作 | 默认执行位置 | 何时需要GPT |
|---|---|---|
| 日常抓取、文字/图片推理、对比、填表 | 本地脚本＋Ollama＋Excel | 不需要 |
| 同版式新增银行/币种 | 本地配置与回归验证 | 现有适配器不能表达时 |
| 条件/产品分类不确定 | 本地复核入口、原始证据 | 需要调整程序规则时 |
| 页面结构改变、解析失败 | 本地保留证据并生成异常摘要 | 根据具体失败补丁修复 |
| 排序/历史/格式检查 | 确定性代码及本地测试 | 业务规则变化或测试失败时 |

每次开发只处理一个可验收批次。先读取PROJECT_STATE.md、当前批次配置和失败摘要，再按需读取相关模块。完整网页、PDF、截图、模型回答和日志保存本机；提供给GPT的材料优先为来源编号、错误位置、必要的原文/截图片段及失败差异。不能为了缩短上下文而省略影响判断的条件。

每批结束更新简短状态：完成范围、验收结果、已知问题、下一批入口。重复业务规则保存在配置和测试中，避免在每轮对话重述。报告生成、统计、回归、截图裁区均由程序完成；GPT主要审查差异和修改相关代码。

不承诺固定token节省百分比。可跟踪开发对话轮数、每批修复轮次、人工时间和本地运行耗时，观察稳定后是否减少维护需求。禁止为了降低本地模型处理量而省略首次验收或必要双路核对。

## 本地效率优化

- 浏览器采集可有限并行；本机4060上的模型请求默认顺序执行，避免显存竞争。Excel写入也保持单任务。
- 每次先完成新采集，再判断文字、截图及关联条件是否可复用。条件或附件变化也触发复核；失败采集不能用缓存冒充新证据。
- 模型、提示词、提取规则、完整输入变化或缓存到期时重新提取。复用结果仍按本期日期判断活动有效性。
- 新运行与断点恢复分开：恢复记录保留原采集日期，跨周任务明确新建一期，不把上周成功批次默认为本周采集。
- 独立部署依赖保存在本机可配置目录，保留现有Excel依赖；固定版本、提供环境检查和恢复方式。无需安装或调用GPT API。
