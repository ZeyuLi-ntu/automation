# 每周运行与历史滚动

本次已经把人工确认的 2026-09-26 七家银行工作簿归档到 `history`，作为后续底稿。原始 9 月 16 日文件不改动。

1. 双击项目目录的 `一键运行.cmd`，采集目前已接通的银行，生成调研、彩虹表及检查页面。
2. 检查新增/变化、异常及模型分歧。两路使用同一本地模型，一致也不代表自动批准。
3. 检查完成后，双击 `确认本期作为历史底稿.cmd`。确认屏幕显示的输出文件夹正确，输入 `YES`。这一动作才会把该版本登记为下次底稿。

## 日期与历史

- 同一天再次运行：在新的输出文件中更新当前日期列，不重复插入相同日期。已确认文件仍单独保留。
- 日期晚于已确认版本：在 SGD 促销 C 列插入本期日期，原日期列整体右移。两期变动始终使用最新列减紧邻上一列。
- 每次使用独立命名的输入明细表。历史公式继续引用各自的旧明细，不会被本期输入覆盖。
- 只滚动目前已接通的 SGD 促销区域；USD/RMB 挂牌历史和其他挂牌矩阵保留现有布局。
- 未采集、已过期或无法确认的本期值显示 `-`，不沿用旧值假装最新，也不自动判定“停止提供”。
- 这是一套按运行日期滚动的流程，没有设置每周自动启动。建议每周固定一天运行。

## 人工修正

在本期输入明细表中修改利率或产品名，确认本期时会登记为可延续修正。下期只匹配同一银行、产品、实际期限、客群、渠道、金额档位和新资金条件；适用条件改变时不强行套用旧修正。产品没采集到或已过期时，旧修正也不能使其重新参与排名。

只修改其中一本工作簿的明细，可以在下一次生成时同步到两本；如果两本被改成不同值，确认程序会停止并指出冲突。当前两本的排序要通过重新生成完成。原始模型响应始终保留，不会被人工值覆盖。

生成的调研表 B 列产品说明若有人工备注，确认时与生成记录比较并登记；下次对应产品继续附带该备注。整行移动、改银行名称、期限或金额条件等结构修改，应先检查映射，不能当成普通利率修正。

新增 UOB、ICBC、BOC。中行 2M、5M 按用户选择留在采集明细，本轮不进入 Excel；4M 归 3M，8M/10M 归 9M，备注保留真实期限。新增产品扩展原银行区块，不另建重复银行名称行。

本期 C 列只显示报价，不显示涨跌箭头。箭头保留在“当日最高报价变动”栏；原有历史条件格式保留。新增行与日期列生成后会检查条件格式的实际适用范围，避免复制行样式时把箭头带入报价栏。

`重新生成已验证表格.cmd` 只使用冻结批次，不重新访问银行。文件内保留各银行真实采集日期；不能把该入口当成下周最新行情采集。

## 出错后

检查页面和运行日志保留在本次输出/运行目录。若中断，一键脚本会给出继续该次运行的位置；已经成功采集的批次可以继续使用。失败和未确认的输出不会自动替换历史底稿。
