# 节省 token 与后续扩展

日期：2026-09-27。日常采集使用本机 Ollama，不依赖本轮对话继续运行。后续促销和挂牌仍需要逐类接入与验收，不能把未适配区域当成已经覆盖。

澄清：这里的 token 是本地模型处理文字/图片的计算单位，不是 GPT API 账单，也不消耗聊天额度。缓存的目的在于减少本机重复计算、运行时间和资源占用，不要求为本地 token 付费。项目已禁用云端模型入口，原理见[完全本地运行说明](完全本地运行说明.md)。

## 已实现

- 期限归组、Personal 优先、最高报价、排序、颜色、历史滚动、Excel 公式和格式由固定代码处理，不调用模型。
- 多银行提取器已加入逐路线精确缓存。新采集单元的文字或图片、提示词、输出格式、模型文件摘要、Ollama 版本和提取器代码完全一致，才复用该路线结果；文字和视觉缓存互不共享。
- 默认缓存有效期 28 天，超期、内容改变、文件损坏、模型/规则改变均重新提取；复用后仍按本期日期核验有效期、字段和双路一致性。不把缓存日期当成网页刚刚采集日期，也不在采集失败时用缓存冒充本期证据。
- 配置位于 config/project.local.json 的 models：shared_response_cache、cache_max_age_days；force_reextract=true 可强制重新提取。缺少可确认的模型版本时关闭跨运行复用。SCB 独立提取器尚未接入跨运行缓存。
- 每个提取单元记录 model_calls、cache_hit、input_tokens、output_tokens 和 reused_tokens。缓存命中本次实际模型调用与输入/输出 token 记零。

实测：Maybank 同一份独立文字/截图证据，在新运行目录复核，两路缓存均命中，新增模型调用 0 次，复用原调用合计 8,739 个 token。记录在 runs/maybank-cache-check-20260927/run.json。该数字是本地模型处理量，不是 Codex 对话额度的节省测量，也不是全项目平均节省比例。

## 后续扩展顺序

1. 先按“网页表格、PDF 表格、图片表格、动态展开页面”建立可复用采集器；同一来源的多币种表只采集一次，再由代码拆分到币种/期限矩阵。
2. 稳定表格用确定性规则提取，模型负责新格式和变化项复核。每个单元必须带关联门槛、资格、起止日期及脚注；不能只截利率数字以减少输入。
3. 保存页面、条件附件与区域摘要。利率不变但条件或附件改变，也进入复核；布局和行数检查发现遗漏时停止该组入表。
4. 新产品、新布局、金额/资格变化或两路不一致必须人工复核；稳定后依验收数据缩小人工范围，同时保留定期全量复查。两路一致不能保证无误，不取消异常拦截。
5. 每次运行生成小报告：本期覆盖、变化、异常、模型调用和缓存命中。维护对话只提供异常区域、来源和差异，不重复粘贴整个工作簿和所有截图。

上述 1–5 是继续扩展的路线，通用多币种解析器及变化优先调度尚未全部实现。先扩展结构相近的挂牌表，再处理特殊投资搭配等复杂促销；每类首次接入均对照原表验收。

## 日常使用

正常每周运行本地“一键运行.cmd”，需要人工修正时打开“人工修正入口.cmd”；模型提取、插表和复核由本地项目执行，无需每周在对话中从头指导。当前 Maybank 本机网络未恢复，因此全量实时流程可能停在该银行；“重新生成已验证表格.cmd”仅重建已保存的证据副本，不能代表新一周已重新采集。

仅在新银行、新页面结构或程序异常时继续维护对话。README、本文、来源配置和验证记录保留当前状态，使后续维护能按问题读取少量文件。
